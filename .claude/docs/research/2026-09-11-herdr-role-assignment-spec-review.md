# delegating-to-herdr-agents 役割分担仕様の成立性レビュー

2026-09-11。ユーザー提案の追加仕様 4 項目が delegating-to-herdr-agents スキルの記述として成り立つかを検討した記録。実装はしていない。

レビューは同一 workspace wE の 2 ペインに並列で依頼した（wE:p3 = cursor、wE:p4 = claude）。スキル自身の「レビューは自分と違う kind へ」方針のドッグフーディングを兼ねる。両者の指摘は司令塔（wE:p1）が herdr CLI の実出力で再検証した。

## 結論

4 項目のうち、原文のまま書いて成立するものは無い。ただし不成立なのは「起動したエージェントがモデルとエフォートを自律的に選択する」の字義どおりの読みだけで、残り 3 項目は書き方を変えれば成立する。

6 論点の判定自体は両レビュアーで一致したが、対処の中身は 2 箇所で割れた。ペイン数の上限は cursor が「司令塔 + 2、4 枚目は確認、5 枚以上は自動作成しない」、claude が「司令塔 + 3、レイアウトから導出」。並列投入の形は cursor が「`--wait` なしの `prompt` → `agent wait`」、claude が「`--wait --until working --until blocked --timeout 10000` で投入 → `agent wait`」。いずれも claude 案を採った。上限は herdr スキル `:104` が既にレイアウト依存の判断を求めているので固定数より導出が整合し、並列投入は `--wait` を省くと 5 秒の stall 検出（`agent_prompt_stalled`）を失うため。

| 論点 | 判定 |
|------|------|
| 1. `agent start` 禁止との矛盾 | 条件付き成立。禁止の理由を絞れば解消 |
| 2. モデル・エフォートの自律選択 | 字義どおりは不成立。主語を司令塔に変えれば成立 |
| 3. 並列性 | 現行の送信手順では不成立。二段階の待ち方に変えれば成立 |
| 4. ペイン数とレイアウト | 条件付き成立。固定数ではなくレイアウトから導出する |
| 5. 分担ゲートの拘束力 | 条件付き成立。herdr 側に強制手段は無い |
| 6. 安全ルールの維持 | 成立。追記 2 点 |

## 論点ごとの詳細

### 1. 既存の `agent start` 禁止と矛盾する

現行スキルは `SKILL.md:20` と失敗表 `:107` で新規エージェントの起動を禁じている。理由は「ユーザーの画面から見えない使い捨ての会話になる」。

このうち「見えない」は、同一タブ内に split した可視ペインには当たらない。herdr スキル `:96` は同一タブの sibling pane を既定とし、`:104-107` が `--cwd "$PWD" --no-focus` での分割手順を示している。見えなくなるのは別タブ・別ワークスペースに立てた場合で、それ自体が `:96` で既に禁じられている。「セッション文脈が続く」という後半の理由は新規ペインに対して事実なので、既存ペインを先に使う根拠として残す。

重要な制約として、`agent start` は対象ペインがインタラクティブなシェルプロンプトにいることを要求する（`herdr agent start --help` の "Existing pane at an interactive shell prompt"、herdr スキル `:58`, `:112`）。現在の wE の 3 ペインはすべて agent が占有しているので、原文の「各ペインで起動する」は既存ペインに対しては実行できない。再利用と新規作成を分けて書く必要がある。

置き換える規則。既存の `idle` / `done` かつ同一 cwd のペインを先に役割へ割り当て、足りない分だけ同一タブを split して、自分が split した空ペインにだけ `agent start` する。tab / workspace の新規作成はユーザーが明示したときだけ。失敗表は「起動するな」から「適任の既存ペインがあるのに起動する、別タブ・別ワークスペースで起動する」へ差し替える。

### 2. 役割に応じたモデルとエフォートを自律的に選択する

原文は選ぶ主体が起動されたエージェント側と読める。その手段は無い。起動後に自分のモデルを変える経路は herdr の agent 系コマンドにも各 CLI にも見当たらず、経路は起動時引数（`herdr agent start <name> --kind <kind> --pane <id> -- <agent-args...>`、herdr スキル `:118-122`）だけ。この引数を組むのは司令塔なので、起動前に役割が確定している必要がある。論点 5 のゲートと同じ順序になる。

実際に `--help` で確認した kind ごとの手段。

| kind | モデル | エフォート |
|------|--------|-----------|
| claude | `--model` | `--effort <low\|medium\|high\|xhigh\|max>` |
| cursor（cursor-agent） | `--model` | モデル名の角括弧オーバーライド（`'...[context=1m,effort=high]'`） |
| codex | `-m` / `--model` | `-c key=value` で config 上書きは可能だが、エフォート相当のキー名は `--help` に出ず未確認 |
| gemini / copilot | `--model` | フラグ無し |
| 上記以外の 17 kind | 未確認（未インストール） | 未確認 |

起動後にプロンプト本文で `/model` を送る案は採用しない。スラッシュコマンドの体系が kind ごとに違ううえ、`agent prompt --help` は投入後 5000ms 以内に `working` か `blocked` の観測が無ければ `agent_prompt_stalled` を返すと明記しており、ピッカー UI を開くだけの入力は stall になり得る（未実験）。

スキルに書くのは kind 非依存の 1 文に留める。役割に応じたモデルとエフォートは司令塔が決めて起動引数で渡す、フラグは kind ごとに違うので実行ファイルの `--help` で確認する、渡す手段が無い kind は既定のまま起動して分担表にその旨を書く。役割とモデルの対応表はスキルに固定しない。

### 3. 並列性は現行の送信手順では得られない

現行スキルは `herdr agent prompt <target> "<依頼文>" --wait --timeout 900000` を唯一の送信形として示す（`:51`, `:54`, 早見表 `:91`）。`--wait` は最初に落ち着いた `idle` / `done` / `blocked` まで呼び出しを止めるので、3 ペインに順に送れば逐次実行になる。`:57` の「待っている間は自分の担当を進めてよい」も、この `--wait` と既に食い合っている。

`agent prompt --help` の実出力で確認した回避策。`--wait --until working --until blocked --timeout 10000` で投入すると、受理されて `working` に入った時点で返るため、stall 検出を残したまま次のターゲットへ進める。全ペインへ投入し終えてから `herdr agent wait <target> --timeout 900000` を順に呼んで回収する。先に終わったペインは `done` で即返る。

このレビュー自体を 2 ペインへ `--wait` なしで投入して並列化し、直後に両ペインが `working` に入ることを確認した。推奨形も実測済みで、`--wait --until working --until blocked --timeout 10000` を `done` 状態のペインへ送ると 419ms で `working` を返した。stall せず即座に次のターゲットへ進める。`--wait` を省いた形には stall 検出が無いので、スキルには `--until working` 形を書く。

### 4. ペイン数とレイアウト

herdr スキル `:104` は同方向の連続 split を戒め、`:96` は tab / workspace の新規作成をユーザーの明示要求が無い限り禁じる。

`herdr pane layout` の実測では、このタブは 265×71 で、右列（132 桁）に 2 ペインを縦に積んだ現状が 36 行と 35 行。司令塔 + 実装 2 + レビュー 2 + 調査 1 の 6 ペインは、3 列 2 行の格子なら約 88×35 で物理的には入るが余裕が無く、2 列 3 行なら約 23 行でコーディングエージェントの差分・承認 UI には足りない。端末がこれより小さければ入らない。

固定数ではなくレイアウトから導出する。split 前に `herdr pane layout --pane "$HERDR_PANE_ID"` で `area` と各 `rect` を読み、1 ペインあたり概ね 80 桁 24 行を下限の目安として、それを割る分割はしない。既定の上限は 1 タブに司令塔 + 3。超える必要があるときはユーザーに確認し、1 ペインが複数の役割を順に担う案と、新しいタブを作る案（ユーザーの明示要求が要る）を提示する。

### 5. 「役割分担を終えるまで作業を開始しない」ゲート

herdr に操作を拒む機構は無い。拘束力はスキル本文の順序とユーザーへの 1 回の確認で作る。分担表を提示して承認されるまで `pane split` / `agent start` / 他ペインへの `agent prompt` / ファイル編集のいずれもしない、と禁止形で書く。

分担表の列は、ペイン（既存の pane_id か「新規」）、役割、担当範囲（触るファイル・ディレクトリ）、kind（新規は既定 `claude`）、モデルとエフォート（渡せる kind のみ）。複数ペインが同一役割を持つ行を許せば、原文の「2 ペインで実装を分担」「複数レビュー担当が別機能を見る」「同一機能を多角的にレビュー」はすべてこの表の重複行として表現できる。「各ペインでどのエージェントを起動するか尋ねる」はこの 1 回の確認に含める。既存ペインの kind は変えられないので、尋ねるのは新規ペインの分だけ。

役割名をそのまま agent 名にはできない。名前の制約は `[a-z][a-z0-9_-]{0,31}` かつ live agent 間で一意（herdr スキル `:60`）で、日本語の役割名は通らない。`herdr agent list` は現時点で 5 ワークスペースにまたがる 15 の live agent を返しており、`reviewer` のような一般名は他ワークスペースと衝突し得る。`impl-1` / `review-auth` のように役割と対象を組んだ ASCII 名にする。既存ペインには `herdr agent rename` で名前を付けられるが、必須にはしない（pane_id で足りる）。

なお現行 `:31` の既定「実装・調査は自分、レビューは別ペイン」は、司令塔が実装しない構成と両立しない。役割分担モードでは司令塔の役割を分担表の作成・依頼・検証・統合・報告に限定する、と書き分ける必要がある。

### 6. 安全ルールは維持できる

cwd 違いのペインへの依頼前確認（`:32`）、`working` / `blocked` には送らない（`:30`, `:55`）、相手の回答は untrusted（`:68`）、統括と最終判断は司令塔（`:11`）はいずれもそのまま効く。

追記が 2 点。split 時は `--cwd "$PWD"` を省略しない（省略時の継承挙動は未確認）。起動直後のエージェントは trust ダイアログ等で `blocked` になり得る（`agent_not_ready`、herdr スキル `:124`）ので、そのときは `:58` の「自分で代わりに答えず、画面を確認してユーザーに知らせる」を適用する。

## 追加仕様に無い欠落

実装担当が 2 ペインになると同一ツリーでファイルとコミットが競合する。分担表で担当ファイル集合を互いに排他にし、コミットは司令塔に寄せるか担当ごとにブランチを分ける。worktree による分離は `herdr worktree` があるが、`:96` によりユーザーの明示要求が要るので既定にしない。

kind をユーザーに尋ねるとき 23 kind を全部提示しない。`command -v` で入っているものだけを候補にする。この環境では claude, codex, gemini, cursor, copilot, kiro の 6 つ。`--kind` の値は `claude` であって「claude code」ではない。

`agent start` は既定 30 秒（最大 300 秒）でタイムアウトする。`agent_not_ready` で返っても名前は残るので `agent read` で画面を確認できる。split したペインの後始末は、可視性が禁止解除の根拠である以上、閉じずに残すかユーザーに聞くのが一貫する。

「同一機能を複数ペインで多角的にレビュー」は、現行 `:31` の「レビュー役は自分と違う kind を優先する」を複数レビュアー間にも広げると意図が通る。

## 反映すべき箇所（未実施）

1. `:20` と失敗表 `:107` を、既存ペイン優先・不足分だけ split・自分が split したペインにだけ start、へ置き換える。
2. 「相方を特定する」の前に「役割分担を決める」節を足す。分担表と確認ゲート、モデル・エフォートの 1 文ルール、レイアウト導出ルールを入れる。
3. 「送信と待機」に並列投入手順（`--wait --until working --until blocked` で投入 → `agent wait` で回収）を足し、`:57` を書き換える。
4. 早見表に「ペインを分割する」「エージェントを起動する」「並列投入する」の行を足す。
5. 失敗表に「`--wait` で順に送って逐次実行になる」「一般名の agent 名が他ワークスペースと衝突する」「実装担当の担当ファイルが重なる」を足す。

「自律的に選択する」という文言は残さない。
