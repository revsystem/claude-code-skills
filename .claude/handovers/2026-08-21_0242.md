## 捨てた選択肢と理由
- Issue/PR本文に移設元 dotfiles への言及を残す案: dotfiles はプライベートリポジトリのため公開側の読み手が理解できない — 「個人環境でローカル配布」という表現に置き換え、コミットメッセージからも除去（2コミットを1本に統合して force-push）
- v1.6.0 の git tag だけを打つ案: `gh skill install` は git tag ではなく GitHub Release の Latest を解決するため、タグのみでは v1.5.0 が配布され続ける — `gh release create` も実行して解決
- 未マージ7ブランチをマージする案: 全て squash-merge 済みの残骸。特に `docs/add-npx-skills-install` は後の gh skill 移行で方針自体が廃止済みで、マージすると現行方針に逆行する — 全削除
- PR本文テンプレートに「変更点は3点までに絞り」を残す案: 「書き方」冒頭の3点ルールと重複して冗長 — 冒頭1箇所に集約し、変更点の段落は設計判断の主旨のみに戻した
- `gh api` でPRマージを通す案: `gh pr merge` がハーネスのクラシファイアにブロックされた際、別経路で同じ操作を通すのはブロックの意図の迂回にあたる — ユーザーに `!` プレフィックスでの手動実行を依頼した

## ハマりどころ
- `gh skill install revsystem/claude-code-skills backlog-create-issue` が `skill not found` で失敗 → タグは push 済みだが GitHub Release が v1.5.0 のままで、install が Release の Latest を参照していた → `gh release create v1.6.0` を実行して解決。以後 `--pin` なしで解決される
- `mise bootstrap dotfiles apply` 実行後も `~/.claude/skills/backlog-create-issue/SKILL.md` の symlink が残存 → mise は `[dotfiles]` から削除されたマッピングの配置先を自動で撤去しない → `command rm -f` + `rmdir` で手動削除（`rm` は `-i` エイリアスのため `command` 経由が必須）
- `git fetch origin main:main` が `refusing to fetch into branch` で失敗 → main を checkout 済みの状態では実行できない → `git fetch origin` + `git merge --ff-only origin/main` に変更
- `find / -iname "SKILL.md" -path "*using-bee*"` が120秒でタイムアウト → WSL2 でルートからの全探索は極端に遅い → `~/.claude` `~/.agents` へ探索範囲を絞る
- `gh pr merge 77` が auto mode クラシファイアにブロックされた → ハーネス側の権限判定 → ユーザーがセッション内で `! gh pr merge ...` を実行して解決

## 学び
- `gh skill install` / `gh skill update` はリポジトリの GitHub Release（Latest）を解決する。git tag を push しただけでは新バージョンが配布されず、新スキルは `skill not found` になる。`--pin <tag>` を付ければタグ直指定で取得できる
- `gh skill install` は配置時に frontmatter を再構成する。キーをアルファベット順に並べ替え、`metadata` ブロック（github-repo / github-ref / github-tree-sha / github-path）を追加する。取得元バージョンが配置ファイル自体から追えるので、`gh skill update` の差分判定もこの tree-sha を使っていると見られる
- `gh skill install` はスキルディレクトリを丸ごとコピーするため `assets/` 配下も配置される。mise の dotfiles symlink はファイル単位の指定なので、`SKILL.md` だけ登録すると assets が欠落する（今回の移設でこの不具合が解消された）
- mise の `[dotfiles]` はエントリを削除しても配置済みファイルを撤去しない。マッピング削除時は手動クリーンアップが必要
- `~/.claude/skills/` には gh skill によるコピー、mise の symlink、`~/.agents/skills/` への symlink が混在しうる。削除前に `ls -la` で実体を確認する
