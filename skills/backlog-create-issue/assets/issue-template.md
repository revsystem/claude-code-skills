# 課題本文テンプレート

必須は Overview / Todo List / References の3セクション。Target environment と Out of scope は条件を満たすときだけ足す。この5つ以外の見出しを増やさない。

スラッシュで併記された見出し（`Overview / Purpose / Background` など）は、そのまま1つの見出しとして書く。いずれかを選ぶ形ではない。

Backlog記法のプロジェクトでは、見出しを `*` / `**` に、リンクを `[[label>url]]` に変換する（backlog-notation スキル参照）。箇条書き `-` とチェックリスト `- [ ]` / `- [x]` は両記法で同じ書き方で通る。ただしチェックリストが機能するのは課題の説明欄だけで、コメント欄では機能しない。

## 骨組み

```markdown
# Overview / Purpose / Background

<この課題で何を変えるか、なぜ必要か。3〜6文>

着手条件: PROJ-98（<その課題で何が揃うか>）の完了後。

# Target environment

- [ ] dev
- [ ] staging
- [ ] production

# Todo List / Complete condition

- [ ] <レビューまたは検証できる単位のタスク>
- [ ] <検証。何をどう見て完了と判断するか>

# Out of scope

- <対象外の項目と、外す理由>

# References / Slack Link

- Parent: PROJ-100
- 前提: [<ドキュメントの題名>](<URL>)（<この課題が前提にする内容>）
- 設計: [<ドキュメントの題名>](<URL>)
- 成果物: [<レポートの題名>](<URL>)、[<手順書の題名>](<URL>)
- 議論: [<チャットスレッドの要旨>](<URL>)
```

## 各セクションの書き方

Overview / Purpose / Background は必須。1段落目は「この課題で何を変えるか」から書き、背景は変える理由を説明するのに要る分だけ足す。「前提条件」「注意点」といった見出しを別に立てず、この節に畳む。着手条件があれば段落の後に `着手条件:` の1行で書く。読者がこの課題単体を読んで、何が済んでいて何が残っているか分かる状態にする。起票後に確定した作業ブランチ名を書く場合も、見出しを増やさずこの節の末尾に1行で足す。

Target environment は複数環境へ順次展開する課題でだけ使う。Overview の直後に置き、チェックボックスをロールアウトの進捗トラッカーとして使う。1環境だけの課題では書かない。1環境内の複数ホストへ順次適用する場合も使わず、Todo List で追う（環境跨ぎか否かで判断する）。

Todo List / Complete condition は必須。完了条件を兼ねるので、検証項目を必ず含める。粒度は SKILL.md 参照。

Out of scope は、意図的に含めない範囲があって書かないと誤解される場合だけ使う。Todo List の後に置く。典型は、ツールの管理外で手作業する手順を柵で囲うケース。

References / Slack Link は必須。1行に1種類の参照を置き、行頭に役割のラベル（`Parent:`、`前提:`、`設計:`、`成果物:`、`議論:` など）を付ける。参照の書き方は次の3つ。

| 参照先 | 書き方 |
|---|---|
| 課題 | 裸のキー（`PROJ-100`）。自動でリンクになる |
| ドキュメント、Wiki、プルリクエスト、チャット | `[題名](絶対URL)`。リンク名には URL やファイル名ではなく、開く前に中身が分かる題名を使う |
| リポジトリ内のファイル | `[題名](リポジトリのファイルURL)`。ファイル名やパスだけを書かない。リンク先は既定ブランチにマージ済みのファイルにする（下記） |

リンク先が何のために要るのか題名だけで伝わらない場合は、リンクの後ろに `（〜の根拠）` のように役割を1句で添える。

リポジトリ内のファイルの URL は `https://<space>/git/<PROJECT>/<repo>/blob/<branch>/<path>` の形になる。作業ブランチのファイルにリンクすると、ブランチの削除やマージ後に辿れなくなる。成果物が作業ブランチにしかない間は、課題の Todo に「既定ブランチへのマージ」を残し、マージ後に既定ブランチの URL へ書き換える。push していないブランチのファイルにはリンクできない。

既存の References に追記するときは、既存の行は内容を残し、記法はプロジェクトの記法にそろえる。同じ役割ラベルの行があればその行に足す。同じリンクを2か所に載せない。

書けるものが何も無くても見出しは消さず、最低でも関連する課題を1つ挙げる。見出しの後半（`/ Slack Link` の部分）は、チームが使っているチャットの名前に合わせて読み替えてよい。
